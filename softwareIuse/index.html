Uses

Everything here earns its place. If a tool doesn't stay small, predictable, and honest about what it does — it's out.

Hardware

Latitude E5470

My main device, running Arch Linux as the only operating system. Studying, coding, all my academic stuff, and of course personal use — everything happens here.

You may ask why Arch specifically? When I choose an OS to live in, it has to satisfy all of these:

  • Kernel + core utils. NO PROGS. (Base image)
  • Open source and free
  • No corp.
  • Does not change UI/look/workflow on its own
  • Does not force updates and upgrades
  • Does not control me
  • Customizable
  • Minimal rolling release
  • Easy to use (does not mean easy to learn*)

Each point could take pages, so headlines only. Arch satisfies all of them — and I've had no problems with systemd (till now), so no need to jump to void.

I use dwl, foot, and wmenu, deliberately following in the footsteps of dwm, st, and dmenu, out of a deep appreciation for the suckless philosophy. I value software that stays small, predictable, and honest about what it does. Minimal storage, minimal CPU and memory usage, and minimal distractions. A workflow that does exactly what I tell it to, and nothing more.

RIP X11, you served your time.

Software

Wayland-based minimalist stack

In pursuit of a lightweight, efficient, distraction-free environment, I deliberately avoided full desktop environments such as GNOME, KDE Plasma, or even lightweight stacks like Xfce. Instead, I built my system around the Wayland display protocol — a modern, secure, low-latency alternative to the traditional X server model.

At the core is dwl, a dynamic tiling Wayland compositor inspired by dwm. dwl preserves the minimal philosophy of suckless tools while leveraging Wayland's cleaner architecture. My configuration focuses strictly on functionality, with only essential patches applied to support my daily workflow.

wmenu

A minimal Wayland-native menu inspired by dmenu. It integrates seamlessly with dwl and avoids any XWayland dependency, keeping the whole graphical stack purely Wayland. I use it to trigger scripts and present minimal selection menus — piping shell output straight into it makes it an essential component in several automation workflows.

foot

My terminal: fast, lightweight, Wayland-native. Given that most of my interaction with the system happens through the terminal, foot is the central interface of my usage.

slstatus

The status bar, if it even deserves the word. slstatus runs in stdout mode and gets piped straight into the compositor — slstatus -s | dwl -s ... — so the entire "bar" is one process writing text into another. No tray, no widgets, no plugin ecosystem, no JSON protocol invented by someone having a rough week. Clock, battery, and the three things I actually look at. Everything else I can read in a terminal like an adult.

vim

The editor I spend the majority of my time in — a complete working environment for programming, note-taking, configuration, and documentation. Modal editing lets me operate with minimal context switching. Config lives at .vim/vimrc in my dotfiles.

tmux

Panes and sessions that outlive whatever I do to the terminal. My config is six lines, and most of them exist to fix exactly one thing: foot's terminfo does not advertise sixel, so tmux quietly refuses to pass image escapes through until you tell it twice — set -as terminal-features ',foot*:sixel' and allow-passthrough on. That is the whole reason images render inside nnn instead of turning my file manager into abstract art.

nnn

File manager that starts instantly and gets out of the way, built from source with my own patch on top. My opener script has one rule, and it is not negotiable: nnn must never be replaced. Text opens in a tmux pane beside it. GUI viewers get detached completely — new session, no tty, no stdio — so dwl tiles them without ever corrupting the TUI underneath.

Previews run side by side through preview-tui, images go through chafa in sixel, bat handles code, fzf handles jumping, and deletions go to trash — I am arrogant, not reckless. Config lives in .config/nnn/, opener included.

swhkd

Global key bindings under Wayland. A hotkey daemon inspired by sxhkd, designed to work cleanly with compositors like dwl. Bindings live at .config/swhkd/swhkdrc.

mako

Notifications — lightweight, built for Wayland compositors, unobtrusive, and no heavy dependencies pulled in.

grim + slurp

Screenshots, decomposed the way Unix intended: slurp selects a region, grim captures it, done. Two small scripts wire them together — one pipes the PNG into wl-copy for the clipboard, the other drops a numbered file into ~/Pictures/Screenshots — and mako confirms it happened. No built-in editor, no cloud upload, no account, no "sign in to continue sharing your own screen".

vim - LaTeX - zathura

These three combined are my studying and note-taking pipeline — summarizing lectures and managing academic work. The plugin code is at .vim/ftplugin/tex.vim in my dotfiles. I wrote all of it myself: there are better options online, but mine do exactly what I need and nothing more, which is the whole point.

newsboat

RSS in the terminal, vim keybindings, around twenty feeds. The algorithm is simple: I subscribed to it, so it appears. Groundbreaking. No recommendations, no engagement optimisation, no feed quietly deciding I need to be angry today. This site ships a feed for precisely the same reason.

irssi

IRC, because parts of the internet got it right in 1988 and then the industry spent thirty years re-implementing it worse, with an Electron wrapper and a 400 MB memory floor. Plain text, plain protocol, runs inside tmux, survives disconnects. Config at .irssi/.

GnuPG (GNU Privacy Guard)

My go-to for locking down everything — emails, photos, backups — because privacy is just common sense. No shady middlemen, no bloated software, just pure control. I trust math over people, and encryption keeps my data mine.

pass + pam-gnupg

My password manager is a directory of GPG-encrypted files and a shell script. One secret per file under .password-store, versionable with git, and readable with nothing but gpg if pass vanished tomorrow. No proprietary vault format, no subscription, no apologetic breach notification email at 2am.

pam-gnupg is the piece that hands my passphrase to the GPG agent at login, so unlocking the machine unlocks the keyring in the same motion. The module is installed; wiring it into the PAM stack is still sitting on my to-do list, where it has been for a while.

My own GPG wrappers

GnuPG is a good engine attached to an interface apparently designed to punish curiosity. Nobody remembers --symmetric --cipher-algo AES256 --output at 3am. So I wrote short shell wrappers and put them in .local/bin:

  • genc / gdec — encrypt and decrypt files or whole directories (a directory becomes .tar.gz.gpg), symmetric by default, -r when I want public-key to a recipient instead
  • gsign / gverify — detached .asc signatures for things I publish or receive
  • gvault — edit an encrypted file in $EDITOR with the plaintext living only in /run/user/$UID (tmpfs, RAM-backed) and wiped on exit, so it never touches the disk
  • gpg-init — build a modern identity: ed25519 certify-only primary, separate sign / encrypt / auth subkeys on a two-year rotation
  • gpg-backup — export secret keys, public keys, ownertrust and revocation certificates into one encrypted archive

Better-engineered options exist. Mine do exactly what I need and nothing else, which — as established — is the entire point.

opendoas

sudo is a large C program with a plugin API, LDAP support, an audit subsystem and a CVE history to match. I wanted to run one command as root. doas is a few thousand lines and a config file you can read in a single breath, which means I can actually audit the thing standing between my user and root. Aliased down to i and u, because typing the full thing forty times a day is not a personality.

QEMU + libvirt + virt-manager

Where everything I do not trust goes. KVM acceleration under QEMU, libvirtd managing the domains, OVMF for UEFI guests, and virt-manager for the rare occasions I would rather click than type. Malware samples, target boxes, a stranger's "just run this script bro", a Windows install that needs to exist and nothing further — all of it behind a virtual NIC I can unplug.

Snapshots are the real feature: a bad afternoon costs a revert instead of a reinstall. It is also why Kali stopped being my host OS. I ran it for a while, learned what it had to teach, and concluded that installing someone else's tool selection as an operating system is a strange way to own a machine. The tools live on Arch now, chosen one at a time, and anything untrustworthy lives in a domain I can delete.

Fonts

JetBrains Mono, Nerd Font patched, size 12, bold — in foot, which means in vim, tmux, nnn and everything else I live in, and serving this very page too. Consistency is free and I refuse to context-switch typefaces.

Arabic is Thmanyah: sans for body text, serif display for headings. A fontconfig rule at .config/fontconfig/conf.d/75-thmanyah-arabic.conf normalises the family names, because the foundry shipped faces called "Thmanyah sans 1.2 Med" and similar crimes against string matching. Same two families are self-hosted here, so Arabic on this site renders the way it renders on my machine.

LibreOffice (docx, pptx, etc..)

For opening documents other people send me. For producing my own, it's vim + LaTeX + zathura, as above.
